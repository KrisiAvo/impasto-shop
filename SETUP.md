# Impasto Atelier — пускане на живо, с реални плащания

Тази папка е цял, работещ магазин: сайтът (`index.html`), плюс два сървърни
файла (`netlify/functions/`), които говорят със Stripe (за плащането) и
Resend (за да изпратят файловете по имейл). Нищо от това не работи, докато
не си направиш собствени акаунти в Stripe и Resend — по-долу е точно как.

## Защо през GitHub, а не с влачене на файл

Предишният вариант (само `index.html`) можеше да се качи с влачене direct в
Netlify. Тази версия има и сървърни функции, а те изискват Netlify да
"build-не" проекта от git хранилище — затова минаваме през GitHub.

## Стъпка 1 — качи папката в GitHub

1. Направи си акаунт в [github.com](https://github.com), ако нямаш.
2. New repository → сложи име (напр. `impasto-shop`) → Create repository.
3. На страницата на новото хранилище избери "uploading an existing file" и
   провлачи **цялата папка** (или всички файлове от нея — GitHub приема и
   папки при drag-and-drop през браузъра).
4. Commit changes.

## Стъпка 2 — свържи Netlify с това хранилище

1. В [netlify.com](https://netlify.com) → Add new site → Import an existing
   project → избери GitHub → избери хранилището `impasto-shop`.
2. Build settings ги остави празни (няма build стъпка) — Publish directory:
   `.` (текущата папка). Deploy site.
3. След deploy-а Netlify ти дава адрес от типа
   `random-name-123.netlify.app`. Може да го смениш от Site settings →
   Change site name.

## Стъпка 3 — направи си Stripe акаунт

1. [dashboard.stripe.com/register](https://dashboard.stripe.com/register) —
   регистрация с имейл. Stripe ще поиска и данни за банковата ти сметка
   по-късно (за да ти превежда парите) — това го попълваш ти лично в техния
   сайт, аз нямам достъп до него и не бива да го правя вместо теб.
2. Първо ще работиш в **Test mode** (превключвателят горе вдясно на
   таблото) — плащанията там са фалшиви, с тестова карта, за да провериш че
   всичко работи, преди да пуснеш истински пари.
3. Developers → API keys → копирай **Secret key** (започва с `sk_test_...`
   в тестов режим).

## Стъпка 4 — сложи ключовете в Netlify

Site settings → Environment variables → Add a variable, и добави:

| Име | Стойност |
|---|---|
| `STRIPE_SECRET_KEY` | ключът от Stripe (Стъпка 3) |
| `SITE_URL` | адресът на сайта ти в Netlify, напр. `https://impasto-shop.netlify.app` (без `/` накрая) |
| `RESEND_API_KEY` | от Стъпка 5 по-долу |
| `FROM_EMAIL` | от Стъпка 5 по-долу |

След добавяне на всяка променлива — Deploys → Trigger deploy → Deploy site,
за да ги приложи.

## Стъпка 5 — направи си Resend акаунт (за изпращане на имейлите)

1. [resend.com](https://resend.com) → регистрация, безплатният план стига
   за начало (3000 имейла/месец).
2. За да пращаш имейли към произволни клиенти (не само към себе си),
   трябва да си верифицираш домейн: Domains → Add domain → въведи домейна
   си (същия, който ще ползваш за сайта) → Resend ти дава 2-3 DNS записа
   → добавяш ги при регистратора на домейна (същото място, където ще
   насочваш и самия сайт — виж по-долу). Отнема от минути до няколко часа.
3. API Keys → Create API key → копирай стойността → сложи я като
   `RESEND_API_KEY` в Netlify (Стъпка 4).
4. `FROM_EMAIL` слагаш нещо от типа `Impasto Atelier <orders@твоя-домейн.com>`
   — трябва да е адрес на верифицирания домейн.
   Докато нямаш верифициран домейн, можеш да тестваш с
   `FROM_EMAIL=Impasto Atelier <onboarding@resend.dev>`, но Resend ще
   позволи да пращаш само към собствения си имейл (този, с който си се
   регистрирал) — не към клиенти. Затова верификацията на домейн е
   задължителна стъпка преди да пуснеш магазина истински.

## Стъпка 6 — свържи Stripe webhook-а

Това е частта, която казва на сайта "плащането мина, изпрати файла":

1. Stripe Dashboard → Developers → Webhooks → Add endpoint.
2. Endpoint URL: `https://твоя-адрес.netlify.app/.netlify/functions/stripe-webhook`
3. Events to send → избери `checkout.session.completed`.
4. Add endpoint. Отваряш новосъздадения endpoint → Signing secret →
   Reveal → копираш стойността (започва с `whsec_...`).
5. Сложи я като `STRIPE_WEBHOOK_SECRET` в Netlify (Стъпка 4) → Trigger
   deploy отново.

## Стъпка 7 — тествай с тестова карта

Докато Stripe е в Test mode, отвори сайта → добави колекция → Checkout →
Pay. На страницата на Stripe ползвай тестова карта:

- Номер: `4242 4242 4242 4242`
- Дата: произволна бъдеща (напр. `12/34`)
- CVC: произволни 3 цифри
- Email: твоя истински имейл (там ще дойде файлът)

След "плащането" би трябвало да получиш имейл с прикачен ZIP на
колекцията до минута.

## Стъпка 8 — премини на истински пари

Когато всичко работи в Test mode: Stripe Dashboard → превключи от Test на
Live (горе вдясно) → Developers → API keys → копирай **Live** secret key
(`sk_live_...`) → замени `STRIPE_SECRET_KEY` в Netlify с него → повтори
Стъпка 6 (webhook-ът в Live режим е отделен от този в Test режим, трябва
да се направи наново с live ключовете) → Trigger deploy.

От този момент истински карти ще плащат истински пари, които влизат по
банковата ти сметка според графика на Stripe (обикновено на всеки няколко
дни, виж Settings → Payouts в тяхното табло).

## Свързване на собствен домейн (по желание)

Site settings → Domain management → Add a domain → следваш DNS
инструкциите на Netlify при регистратора на домейна ти. След като
домейнът е активен, обнови `SITE_URL` в Netlify environment variables
на новия адрес и Trigger deploy — иначе Stripe ще пренасочва клиентите
към стария `.netlify.app` адрес след плащане.

## Какво получава клиентът

При успешно плащане Stripe извиква `stripe-webhook.js`, който взима
имейла на клиента от самата Stripe сесия и прикача ZIP файл с купените
картини (пълна резолюция, без воден знак — файловете в
`netlify/functions/deliverables/` не са публично достъпни никъде другаде
по сайта, стигат само по този път). Клиентът вижда и обикновена Stripe
разписка по имейл — това е отделно, автоматично от самия Stripe.

## Ценоразпис (можеш да го смениш)

Цените живеят в `netlify/functions/create-checkout.js`, в обекта
`PRICES` — стойностите са в центове (`490` = €4.90). Промяна там изисква
нов commit + push в GitHub, Netlify ще пусне нов deploy автоматично.
